## Названия и адреса проектов

Использовать только следующий формат. В новых названиях и адресах не добавлять
слова `REALIZED`, `NEW` и номера вида `01`/`02`.

| Название | Хеш в превью | Подробная страница |
|---|---|---|
| OSTROV I | `#ostrov-i` | `/projects/ostrov-i/` |
| MIHALKOVO PARK | `#mihalkovo-park` | `/projects/mihalkovo-park/` |
| AVENUE PARK | `#avenue-park` | `/projects/avenue-park/` |
| NOVOPESCHANAYA | `#novopeshchanaya` | `/projects/novopeshchanaya/` |
| OSTROV II | `#ostrov-ii` | `/projects/ostrov-ii/` |

Те же slug используются в `assets/js/projects.js`, папках превью,
`assets/data/project-details.json`, адресах подробных страниц и `sitemap.xml`.
Старые хеши в `assets/js/projects.js` оставлены только для совместимости со
старыми ссылками. Содержимое превью MIHALKOVO PARK и AVENUE PARK уже обменяно
местами в соответствии с последним согласованием.

## Важные решения по интерфейсу

- в шапке активный раздел выделяется цветом и подчёркиванием;
- в галерее активный проект выделяется в горизонтальной полосе названий;
- отдельный крупный повтор названия проекта убран;
- основное изображение не кадрируется серым фоном и сохраняет пропорции;
- миниатюры сохраняют ориентацию кадра;
- клик по фотографии открывает её крупно, в просмотре доступны стрелки,
  свайпы и клавиатура;
- на подробных страницах фотографии на десктопе должны помещаться в окно и
  сохранять светлое пространство вокруг;
- мобильная полоса проектов не должна самостоятельно прокручиваться по
  вертикали;
- сайт сохраняет минималистичную светлую подачу и спокойную типографику.

## Важные файлы

- `assets/css/styles.css` — все общие и адаптивные стили;
- `assets/js/main.js` — меню, переходы и главная карусель;
- `assets/js/projects.js` — список и логика превью проектов;
- `assets/data/project-details.json` — порядок и группировка полных галерей;
- `scripts/build-project-pages.mjs` — генерация подробных страниц;
- `scripts/check-site.mjs` — проверка сайта;
- `BACKLOG.md` — единственный актуальный список следующих задач;
- `AUDIT.md` — результаты последнего технического аудита.

После изменения `assets/data/project-details.json` выполнить:

```bash
node scripts/build-project-pages.mjs
```

## Порядок работы и публикации

1. Выбрать одну задачу или одну группу тесно связанных правок из backlog.
2. До редактирования проверить `git status` и не затрагивать чужие изменения.
3. Внести все связанные правки и проверить их локально одной итерацией.
4. Выполнить:

   ```bash
   node scripts/check-site.mjs
   node --check assets/js/main.js
   node --check assets/js/projects.js
   ```

5. Сделать один осмысленный коммит и один push для всей группы.
6. Дождаться GitHub Pages и проверить опубликованный сайт один раз после
   завершения группы, а не после каждого небольшого отступа или переименования.
7. Обновить `BACKLOG.md`, если задача выполнена или появились новые пункты.
